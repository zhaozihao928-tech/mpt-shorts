# MPT Shorts · 手机端生成的竖屏短片

用 Termux（Ubuntu 容器里的 MoneyPrinterTurbo）+ 自写的分镜渲染器 `mpt-short`，在手机上生成的中文竖屏短片。
每个目录是一支成片：视频、字幕、分镜源文件、封面帧。

## 和「随便配素材」的区别

分镜里每一段都有自己的角色：

- `clips`：旁白讲的是**能拍出来的东西**时，才按关键词取图库素材（宇宙、钟摆、乱房间、齿轮……）；
- `diagram`：旁白在讲**概念链条**时，画面是程序画出来的信息图（约束 → 概率 → 因果 → 熵 → 信息 → 反馈 → 演化），逐级出现；
- `text`：结尾用黑底大字给结论，配音乐收尾。

旁白由当前会话按脚本写，配音用 Edge TTS（免费），字幕强制单行并按字数比例分配时长。

## 为什么一次比一次快

| 做法 | 9 个素材片段的合成耗时 | 整片全流程 |
|---|---|---|
| 单趟 12 路并发拼接 | 499 秒 | 596 秒 |
| **逐片编码 + 无损拼接** | **80 秒** | **204 秒** |
| 分镜未改动（命中构建缓存） | — | **0.13 秒** |

三个机制：

1. **共享素材库**：图库素材按关键词在首次下载时就归一化成 720×1280，存进公共库；后续任何片子复用同一个词条都不再下载、不再缩放。
2. **逐片编码 + 无损拼接**：手机 CPU 不适合十几路解码并排跑，改成一段一段编码（时长精确到帧、相加等于旁白时长），最后 `-c copy` 拼接，不再二次编码。
3. **时间轴对齐**：每段旁白后补 0.35 秒静音再拼接，避免多段累计漂移（11 段曾累计 3.86 秒）。
4. **构建缓存**：分镜 JSON 的哈希与上次一致时，直接交付上次成片（0.13 秒），只在改动时才重渲染受影响的片段。

## 复现

```sh
mpt-short build /绝对路径/storyboard.json   # 生成
mpt-short build ... --force                 # 忽略缓存重做
mpt-short report                            # 每次流程的分阶段耗时
```

分镜格式见 [`shorts/2026-09-16-world-logic/storyboard.json`](shorts/2026-09-16-world-logic/storyboard.json)。
